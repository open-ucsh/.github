# Convención de nombres para repositorios

Los repositorios de Open UCSH usan nombres descriptivos y consistentes para que sea fácil encontrarlos y entender qué hace cada proyecto.

Esta convención es obligatoria para los nuevos repositorios. El nombre final se acuerda entre los mantenedores y quien propone el proyecto.

## Formato

Usamos minúsculas, palabras separadas por guiones y nombres en español, sin tildes ni caracteres especiales. Se permiten abreviaturas conocidas, como `bd`, siempre que el nombre siga siendo claro.

El nombre debe seguir este formato:

`prefijo-nombre-del-proyecto`

## Prefijos

| Prefijo | Uso |
| --- | --- |
| `web-` | Sitios y aplicaciones web, incluso si incluyen backend |
| `api-` | APIs y servicios mantenidos en un repositorio separado |
| `app-` | Aplicaciones móviles o de escritorio |
| `tool-` | Herramientas de línea de comandos, scripts y otras utilidades |
| `docs-` | Repositorios dedicados a documentación |
| `template-` | Plantillas para iniciar proyectos |

## Ejemplos

- `web-modelador-bd`
- `web-diagrama-de-venn`
- `api-biblioteca`
- `app-agenda-estudiantil`
- `tool-conversor-datos`

## Cómo elegir un nombre

El nombre debe describir la función o el tema principal del proyecto. Evitamos nombres genéricos como `proyecto-final`, `prueba` o `sistema`, y no agregamos `open-ucsh`, porque la organización ya identifica a quién pertenece.

Open UCSH acepta proyectos educativos, herramientas y otros recursos útiles para aprender. Si un proyecto nace en un curso y se aporta a la organización, su nombre sigue esta misma convención: describe lo que hace, sin necesitar el nombre del curso, el semestre o el año.
